qrdrop

Send a file straight from one device to another. A QR code carries the key; the file goes over WebRTC; nothing in between ever holds a readable copy.

What this does and does not protect
  • Files are encrypted end to end under a key derived from the QR code, on top of WebRTC's own encryption. Relays and TURN servers see ciphertext and byte counts, never contents.
  • Each transfer uses fresh keys. A code captured later cannot decrypt a transfer that already happened.
  • Anyone with the code can join. It is the entire credential. Show the QR to the person you mean to send to, and not to a room.
  • Both devices learn each other's IP address. That is inherent to a direct connection.
  • Code is self-hosted, not loaded from a CDN. This page serves a bundle built from source, so the jsDelivr risk that used to be listed here is gone. What remains: the server hosting this page could still serve modified code, the same way any web app's server could. No in-browser design prevents that. For genuinely sensitive material, use a tool you can verify before running.
